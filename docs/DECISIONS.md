# Decisions log

Choices not covered by `Dealership Platform – Build Plan.md`. Append one bullet per decision, with the agent name.

## Foundation (M1)

- **[Foundation] Package name and source exports.** Shared code is `@sda/shared` (`packages/shared`). It exports **TypeScript source** (no build step). Next.js compiles it via `transpilePackages`; functions bundle it with tsup (esbuild) so the deployed functions package has no `workspace:` dependency; vitest/tsx run it directly.
- **[Foundation] Functions deploy layout.** `pnpm --filter functions build` bundles `functions/src/index.ts` to `functions/lib/index.js` (CJS, node20) and writes `functions/lib/package.json` with runtime deps only (`scripts/prepare-deploy.mjs`). `firebase.json` uses `"source": "functions/lib"` for deploy and the emulator. Emulator env files (`functions/.env.local`, `.secret.local`) are copied into `lib/` by the build.
- **[Foundation] Node 20 for functions** as the plan says. Note: Google's Node 20 runtime reaches end of support around Oct 2026, so plan a move to `nodejs22` (change `engines`, `firebase.json` runtime and the tsup target) – ask the orchestrator first.
- **[Foundation] Version pins.** Next 15.5, React 19, Tailwind 4, zod 4, firebase 12 / firebase-admin 13 / firebase-functions 6, `@firebase/rules-unit-testing` 5 (v6 needs Node 24), TypeScript 5.9 (typescript-eslint doesn't support TS 7 yet), ESLint 9 (flat config), vitest 3, `@tanstack/react-table` 8 (shadcn data-table examples target v8).
- **[Foundation] Emulator ports are non-default** (UI 4010, hub 4410, auth 9109, firestore 8188 (ws 9159), functions 5011, storage 9209, logging 4510) so this project runs alongside other Firebase projects' emulators on the same machine. The single source of truth for code is `EMULATOR_PORTS` in `@sda/shared` (must match `firebase.json`).
- **[Foundation] Java for the Firestore emulator.** `scripts/with-java.sh` finds a Java 11+ runtime (Homebrew `openjdk@21` is installed on the dev Mac; the system default is Java 8) and is used by `pnpm emulators` and `pnpm test:rules`.
- **[Foundation] GST rate is stored as a percent** (`settings/business.gstRate = 10`), matching `indicativeRatePct`. Money helpers take percents.
- **[Foundation] Date fields.** Stored documents use Firestore Timestamps. Form and callable inputs use strings: date-only fields are `YYYY-MM-DD` (converted at midnight Australia/Perth via `dateKeyToTimestamp`), instants are ISO strings with an offset (e.g. `2026-10-27T09:00:00+08:00`). Each entity has `xxxInputSchema` (forms/callables) and `xxxSchema` (stored doc).
- **[Foundation] Audit fields are enforced by the rules.** Client creates must set `createdAt/updatedAt = serverTimestamp()`, `createdBy/updatedBy = uid`, `deletedAt = null`; updates must set `updatedAt/updatedBy`. Use `createFields(uid)` / `updateFields(uid)` from `apps/web/lib/firebase-writes.ts`.
- **[Foundation] Soft delete is admin-only** for every collection (setting/clearing `deletedAt`/`deletedBy`); hard deletes are denied to all clients. Soft-deleting a car must also set `published=false` (public reads are keyed on `published` only).
- **[Foundation] Bookings: dashboard edits.** Staff/admin may update only `status` and `notes` on a booking from the client. Cancelling from the dashboard is a status change; a new trigger stub `onBookingStatusChange` (functions) releases the slot lock / count. `slotLocks`, `slotCounts`, `stripeEvents` are functions-only.
- **[Foundation] Enquiries: dashboard edits** limited to `status`, `assignedTo`, `notes`, `bookingId`.
- **[Foundation] Deposits: admin may only mark a conflict resolved** (`conflictResolvedAt`, `conflictResolvedBy`, `conflictNote`) – the plan says conflicts are "marked resolved in admin" while deposits are functions-write.
- **[Foundation] Extra settings docs.** `settings/legal` (privacy, terms, deposit terms, warranty text – public read) for the "legal text" settings tab, and `settings/app` (aged stock threshold, next stock number – staff read, admin write). `settings/deposit` also stores `termsVersion`.
- **[Foundation] Users collection: staff can read only their own doc** (exactly as the plan). Screens that need other users' names for staff (salesperson / assignee pickers) need a callable or denormalised names – Admin/Functions agents to decide.
- **[Foundation] Extra callable `getManagedBooking`** (public, token-checked) for the customer booking page `/booking/[id]?t=token`, since customers can't read `bookings`.
- **[Foundation] Stock numbers** are `SDA` + digits (no hyphens, they end the slug). `stockNoFromSlug` relies on this.
- **[Foundation] Status rules** (`@sda/shared` `canTransitionCar`): Draft→Available needs ≥1 photo, price, make/model/year; Reserved→Available (release) and Sold→Withdrawn are admin-only; Withdrawn→Draft/Available allowed to re-list.
- **[Foundation] Finance calculator**: standard amortisation; monthly n = term, r = rate/12; weekly n = term×52/12, r = rate/52.
- **[Foundation] Public SSR reads use the Firestore REST API** (`apps/web/lib/server/firestore-rest.ts`) because firebase-admin (gRPC) doesn't run on Cloudflare Workers. Locally it hits the emulator unauthenticated (rules apply). In staging/prod, set the Cloudflare secret `FIREBASE_SERVICE_ACCOUNT_JSON` (read-only Datastore viewer service account) so SSR keeps working once App Check is enforced; the read layer always filters `published == true`.
- **[Foundation] Images.** Car `images[].id` is a Cloudflare Images id, or `local:<path>` for seed/dev files under `apps/web/public/images/<path>`. A global next/image custom loader picks the smallest Cloudflare variant (thumb 400 / card 800 / full 1600) for each requested width. Missing images fall back to `/placeholder-car.svg`.
- **[Foundation] Seed photo mapping.** Seed cars use `local:cars/car-01.webp` … `car-12.webp`: 01 Toyota Hilux, 02 Ford Ranger, 03 Mazda CX-5, 04 Hyundai i30, 05 Toyota RAV4, 06 Kia Sportage, 07 Mitsubishi Triton, 08 VW Golf, 09 Subaru Outback, 10 Nissan Patrol, 11 Toyota Corolla, 12 Mazda3 (matches `apps/web/public/images/cars/manifest.json`; seed colours match the photos). Cars 13–20 reuse the photo of the same model.
- **[Foundation] Fonts.** Display: **Archivo** (variable, width axis; used heavy and slightly expanded) → `font-display`. UI: **Geist** → `font-sans`. Numbers/IDs: **Geist Mono** → `font-mono`. All via `next/font/google` in `app/layout.tsx`.
- **[Foundation] Dark sections.** Brand tokens flip per section: put `className="dark"` on a section to use the dark token set inside a light page (shadcn's `dark` variant is `&:is(.dark *)`).
- **[Foundation] 2FA for admin** is not enforced in Firestore rules (would block the emulator and seed users); enforce it in the admin login flow (M2) and optionally later in rules via `request.auth.token.firebase.sign_in_second_factor`.
- **[Foundation] App Check.** Callables use `enforceAppCheck` automatically outside the emulator (opt out with `ENFORCE_APP_CHECK=false`). The web client initialises App Check only when `NEXT_PUBLIC_APPCHECK_SITE_KEY` is set and emulators are off.
- **[Foundation] Secrets in functions** are declared with `defineSecret` (`SECRETS` in `functions/src/core/config.ts`) but read through `env()`, which falls back to `process.env` and `''` so missing keys degrade gracefully (Turnstile → always-pass test secret; email → logged).
- **[Foundation] OpenNext incremental cache** is not configured yet (needs an R2 bucket). Add it when staging resources exist so `revalidateTag` works on Cloudflare.
- **[Foundation] Lint** runs from the root flat config (`eslint.config.mjs`); `next build` skips lint. Generated shadcn files in `components/ui` are excluded from lint and Prettier.
- **[Foundation] `.gitignore`** no longer ignores every `lib` folder (it would have hidden `apps/web/lib`); it ignores `/functions/lib` only.

## Admin dashboard (M2/M3/M5/M6/M7 admin UI)

- **[Admin] Route layout.** `app/admin/layout.tsx` (server, noindex metadata) wraps everything in `components/admin/providers.tsx` (next-themes with storage key `sda-admin-theme`, AuthProvider, sonner). `/admin/login` sits outside the shell; every other page lives in the route group `app/admin/(app)/` whose layout is `<AdminShell>` (auth guard → `/admin/login?next=…`; a signed-in user without a role claim is signed out). The old Foundation placeholder `app/admin/page.tsx` was replaced by `app/admin/(app)/page.tsx`.
- **[Admin] Role gating, two layers.** (1) Nav: `components/admin/shell/nav-config.ts` marks Deposits, Reports, Users, Settings as `role: 'admin'`; staff never see them (sidebar, phone bottom bar, More drawer). (2) Routes: those pages render inside `<AdminOnly>`, so for staff the page component (and its data loading) never mounts – they get a "Admins only" state. Car page tabs Financials and Activity are not rendered for staff; Overview only loads carFinancials/expense totals when `isAdmin`; the Sale tab only reads deposits for admins. Staff therefore never request carFinancials, deposits, users list (falls back to their own user doc) or the audit log.
- **[Admin] Activity tab is admin-only** because `auditLog` is admin-read in the rules (the plan's car tab list doesn't mark it either way).
- **[Admin] Theme.** The `dark` class is toggled on `<html>` (so portalled sheets/popovers theme correctly) and removed when the admin unmounts. The sidebar and phone bottom bar are always near-black (`dark` token set + `bg-brand-black`). Admin-only CSS (touch targets ≥44px on coarse pointers, tabular numerals, press feedback, lifting the root "Preview" badge above the phone bottom bar) lives in `components/admin/admin.css`, scoped to `.sda-admin` – `globals.css` untouched.
- **[Admin] 2FA step.** The login screen has a TOTP step. Demo: the admin account always goes through it (any 6 digits). Firebase: on `auth/multi-factor-auth-required` the step is shown but can't complete yet – **needs Foundation**: `useAuth()` should expose an MFA challenge (e.g. `signIn` resolving to `{ mfaRequired: true, verifyTotp(code) }` via `getMultiFactorResolver` + `TotpMultiFactorGenerator`) and a TOTP enrolment helper for first admin sign-in. The admin can't import `firebase/auth` itself.
- **[Admin] Stock numbers for new cars** = `SDA` + max(highest existing SDA number + 1, `settings/app.nextStockNo`). The admin never increments `settings/app.nextStockNo` because staff can't write settings; `onCarWrite` (functions) could bump it if we want the counter authoritative.
- **[Admin] Publishing.** "Publish" on a Draft car also moves it to Available (validated by `canTransitionCar`, which needs ≥1 photo, price, make/model/year). Withdraw and Back-to-draft also set `published=false`. "Mark sold" opens the Sale tab; saving a new sale sets `status: 'sold'` + `soldAt` on the car. Release (Reserved → Available) is admin-only and clears `reservedAt`.
- **[Admin] Photos.** Firebase mode: `getImageUploadUrl` → multipart POST to the Cloudflare direct-upload URL with XHR progress (3 at a time), image ids appended to `car.images` after each upload; delete calls `deleteCarImage` for Cloudflare ids. The first image is always the cover (`isCover` + `order` are normalised on every save). Demo mode: photos are downscaled in the browser (720px JPEG) and stored as `data:` URLs so they survive reloads in the localStorage overlay (large batches may hit the ~5 MB localStorage quota; the overlay then keeps them in memory only).
- **[Admin] Receipts and sale documents need a Storage helper.** The repository has no upload / download-URL methods for private files and the admin can't import `firebase/storage`. **Needs Foundation**: add to `AdminRepository` e.g. `uploadPrivateFile(path, file, onProgress?) → path` and `getFileUrl(path) → short-lived URL` (Firebase: Storage `uploadBytesResumable` / `getDownloadURL` or a callable that signs). Until then, in Firebase mode an expense/sale saves without the file (with a warning toast) and `/admin/receipts/[...path]` explains it isn't connected (it already calls `repo.getFileUrl(path)` when that method exists). Demo mode keeps uploaded files as object URLs for the browser session. Paths: `receipts/{carId}/{timestamp}-{file}`, `sales/{carId}/{timestamp}-{file}`.
- **[Admin] Salesperson / assignee pickers** use `listUsers()`; when that is denied (staff) they fall back to the signed-in user's own doc. A names callable or denormalised names would let staff pick colleagues.
- **[Admin] Trade-in on a sale** can create a linked Draft car (default transmission automatic / fuel petrol / price 0, staff editable later); for admins it also writes `carFinancials` for that car (source trade-in, purchase price = trade-in value).
- **[Admin] Deposit terms version.** Saving a changed deposit terms text in Settings sets `termsVersion` to `{YYYY-MM-DD}-{random}` so each deposit records which wording was accepted.
- **[Admin] Demo exports** import the Functions agent's builders from `@sda/shared/reports` (dynamic import, so exceljs only loads on the Reports page) and feed them the same `ReportSource` shape the functions build from Firestore, built from the demo repository.

## Functions agent

- **[Functions] `@sda/shared/reports`** (the one shared edit allowed). Multi-file module `packages/shared/src/reports/` (types, sheet helpers, car-report, stock-report, csv, source), subpath export `./reports`, `exceljs` added as a shared dependency. It is NOT re-exported from the package root (keeps exceljs out of bundles). Inputs are plain objects with `Date`s; `reportSourceFromDemo(buildDemoDataset())` / `carReportDataFromSource` / `stockReportDataFromSource` make them from raw collections, so the export functions and the admin demo mode share one code path.
- **[Functions] Report details.** Header row: bold white on graphite `#17181B`, frozen, autofilter; fitted widths; `$#,##0.00`, `dd/mm/yyyy`, `0.00%`. Totals, Summary costs, By Category (SUMIF), gross profit, margin and every Overview figure are formulas over bounded ranges (`F2:F{n}`, never whole columns, so totals rows aren't double-counted), with cached results and `fullCalcOnLoad`. With no data rows the ranges point at the header row so totals stay formulas (=0) without circular references. Dates are written as the Perth calendar date (UTC midnight) so Excel doesn't show the previous day. Header/footer: business name, sheet, period, generated date, page x of n. Receipt cells link to `{SITE_URL}/admin/receipts/{path}` (each segment URL-encoded) – never a signed URL. Stock Summary = cars in stock at any time in [from, to] (purchased ≤ to and unsold or sold ≥ from); `status` filters cars, `category` filters the Expenses / By Category sheets only (Stock Summary keeps lifetime expense totals so profit stays correct). CSVs (`csv-stock`, `csv-expenses`) are values, CRLF, UTF-8 BOM from the function.
- **[Functions] Exports storage.** `exports/{uid}/{timestamp}_{fileName}` (download name = plan file name). Deployed: V4 signed URL, 15 min – the runtime service account needs *Service Account Token Creator* (signBlob). Emulator: a download-token URL (signing needs real credentials). New scheduled `cleanupExports` (hourly) deletes exports older than 24 h; a bucket lifecycle rule would work as well.
- **[Functions] Build fix (important).** tsup `clean: true` followed the `functions/lib/node_modules → ../node_modules` symlink that `prepare-deploy.mjs` creates. On the second build it deleted files through it: `functions/node_modules/*`, their copies in the root `node_modules/.pnpm`, and `packages/shared` source (through the `@sda/shared` workspace symlink). tsup now runs with `clean: false`; `functions/scripts/clean-lib.mjs` empties `lib/` without following symlinks (`pnpm --filter functions build` calls it first). Verified: two consecutive builds leave shared and node_modules untouched.
- **[Functions] Secrets** are bound per function with `bindSecrets(...)` on deploy and not bound in the emulator (a demo- project has no Secret Manager). Every bound secret must exist in Secret Manager; use the value `unset` for keys not available yet (`env()` treats `unset`/`-` as missing).
- **[Functions] Graceful degradation.** No `RESEND_API_KEY` → emails are logged. No Turnstile secret → always-pass test secret. No `STRIPE_SECRET_KEY` → the deposit is created `pending` with session id `cs_dev_<depositId>`, and the success URL is returned without charging anything. A live `sk_live_` key is refused in the emulator. No `STRIPE_WEBHOOK_SECRET` → the webhook answers 503 (it never processes an unverified event). No Cloudflare Images credentials → `getImageUploadUrl` / `getTradeInUploadUrls` throw `failed-precondition` "Photo uploads are not configured yet" (the trade-in form should still send without photos); deletes and cache purges are logged. No `STOCK_FEED_KEY` → feed answers 503.
- **[Functions] Bookings.** Slot lock `slotLocks/{carId}_{YYYYMMDD_HHmm}` via `tx.create` + `slotCounts/{YYYYMMDD_HHmm}` capacity check in the same transaction (`maxAttempts: 10`; contention surfaces as `aborted`). Errors: `already-exists` (slot taken), `resource-exhausted` (slot full), `failed-precondition` (not a valid open slot / car not bookable). `staffCreateBooking`, and `getAvailability` when called by staff or an admin, ignore `minNoticeHours` (phone bookings); every other rule still applies. Manage tokens: 24 random bytes base64url, stored as SHA-256 hex, compared in constant time; a wrong token and a missing booking both return `not-found`. `onBookingStatusChange` releases the lock only if it is still held by that booking (idempotent with `cancelBooking`, which releases inside its own transaction). Re-confirming a cancelled booking from the dashboard does NOT re-take the slot.
- **[Functions] Reminders.** Hourly: confirmed bookings starting within the next 24 h, booked ≥ 24 h ahead, with no `reminderSentAt`. Each booking is claimed in a transaction before sending; the claim is reset if the send fails. The reminder can't include the manage link (only the token hash is stored), so it points to the confirmation email and the contact page.
- **[Functions] Deposits.** Checkout: `payment` mode, AUD, unit amount = `settings/deposit.amountCents` exactly, line item `Deposit – {year make model variant} ({stockNo})`, `customer_email`, metadata `{depositId, carId, termsVersion}` (also on the PaymentIntent), `expires_at` = now + 31 min (Stripe's minimum is 30 min, so a 1-minute margin), `custom_text.submit` = "NON-REFUNDABLE DEPOSIT of $X." + terms text (cut to Stripe's 1200 characters), idempotency key `deposit-{id}`, `cancel_url` `/reserve/cancelled?car={slug}`. `termsVersion` must match `settings/deposit.termsVersion`, otherwise `failed-precondition`. Webhook: `stripeEvents/{event.id}` is written in the SAME transaction as the deposit/car change, so a replay is a no-op. It also handles `checkout.session.async_payment_succeeded`, and a `completed` event with `payment_status != paid` waits for it. The conflict email goes to every active admin in `users` plus `DEALERSHIP_NOTIFY_EMAIL`.
- **[Functions] Users.** `inviteUser` creates the Auth user (no password), sets the claim, writes `users/{uid}` and emails a Firebase password-reset link as the invite; the link is also returned when the email was only logged (or in the emulator). `setUserRole` reactivates a deactivated user and can't remove the caller's own admin role. `deactivateUser` removes the role claim, disables the account, revokes refresh tokens and sets `active=false`; you can't deactivate yourself.
- **[Functions] onCarWrite** keeps `slug` and `searchText` (`make model variant stockNo rego`, lowercase) in sync. It ignores events that only change those derived fields (loop guard), writes the audit entry (actor = `updatedBy`; action create / update / status-change / publish / unpublish / delete / restore), and purges `/cars/{old,new slug}`, `/cars`, `/` and `/sitemap.xml` when the car is or was public. It does not call Next's `revalidateTag` (no revalidation endpoint exists yet); pages rely on their 60 s revalidate.
- **[Functions] stockFeed (M8).** GET `?key=` or `X-Feed-Key`, `?format=xml` (JSON by default), optional `?channel=carsales|gumtree|facebook`. Only published + available + not deleted + toggled cars, read fresh on every request with `Cache-Control: no-store`. Image URLs use the new env var `CF_IMAGES_DELIVERY_URL`. Not done: a persisted sync log (it would need a new collection plus rules) – requests are only logged.
- **[Functions] Emails** are React Email templates in `functions/emails/` (layout: black header + chrome logo `/brand/logo-full-transparent.png`, red rule, business footer). The `react-email` preview CLI was not added (heavy; rendering uses `@react-email/render`). New dependency: `ics`.
- **[Functions] Tests.** `pnpm --filter functions test` = unit tests. `pnpm --filter functions test:emulator` starts the Firestore, Auth and Storage emulators and runs `test/emulator/**` (`.run()` on the real function objects).

## Web stack change

- **[Web] Next.js → Vite + React SPA (owner decision; overrides the Next.js/OpenNext stack in the build plan).** `apps/web` is now Vite 7 + React 19 + React Router 7 (data mode, `createBrowserRouter` in `app/routes.tsx`, every route module lazy-loaded so the public site and `/admin` are separate chunks), Tailwind v4 via `@tailwindcss/vite`, fonts self-hosted with `@fontsource-variable/*` (same `--font-*` variables). Route modules keep the old `app/` layout: they export `loader` (calls `@/lib/data/public`, which now runs in the browser – demo fixtures, or the Firestore client SDK under the existing public-read rules; memoised 60 s), `metadata` or `meta(data)` (applied by `useDocumentMeta`, `lib/meta.ts`), and the page component. Thin shims keep the component code unchanged: `@/components/link` (router `Link` with `href`), `@/lib/navigation` (useRouter/usePathname/useSearchParams/notFound), `@/components/img` (lazy `<img>` + Cloudflare Images srcset). Env vars are `VITE_*`. Deploy target is a static Cloudflare Pages site (`public/_redirects` SPA fallback, `public/_headers` noindex for /admin + immutable `/assets`); `pnpm build` sets `SDA_DEPLOY_ENV=production` and refuses demo mode. Removed: next, @opennextjs/cloudflare, wrangler.jsonc, the Firestore REST/SSR read path, the image loader and revalidation (functions' Cloudflare cache purge of `/cars/*` is now harmless but unnecessary). **SEO trade-off:** car pages are client-rendered – titles, descriptions, canonical, Open Graph tags and the JSON-LD `<script>` are set in the browser, so crawlers that don't run JS (most social link previewers) only see the static defaults in `index.html`. `robots.txt` is static in `public/`; `sitemap.xml` is generated at build time (`scripts/generate-sitemap.ts`) from the shared demo/seed fixtures, so in production it lists the seed cars, not live Firestore stock – regenerate from Firestore (or add a Pages Function) if live car URLs are needed. Demo builds add a `noindex` meta to `index.html` and a disallow-all robots.txt.
